> 📂 **FileInspector** walks a directory tree and produces a structured
> inventory of everything in it — with the metadata *inside* each file, not
> just its name — as JSON, XML **or** CSV.

Loosely inspired by JAM Software's FileList, which does exactly this job and
only runs on Windows. FileInspector keeps the command-line-first design and
runs identically on macOS, Windows and Linux.

---

## ⚙️ How It Works

```
  fileinspector ./archive --format json --exif --min-size 1MB
        │
        ▼
  ┌──────────────────┐
  │ 1. Walk tree     │  depth limit, follow-symlink policy
  └────────┬─────────┘
           ▼
  ┌──────────────────┐
  │ 2. Filter        │  name · ext · date · depth · size · attrs
  └────────┬─────────┘
           ▼
  ┌──────────────────┐
  │ 3. Base metadata │  path, size, created/modified/accessed
  └────────┬─────────┘
           ▼
  ┌──────────────────┐
  │ 4. Deep metadata │  by type ─┬─ 🖼️ EXIF   (photos)
  │    (optional)    │           ├─ 🎵 ID3    (audio)
  └────────┬─────────┘           └─ 📄 author, pages (docs)
           ▼
  ┌──────────────────┐
  │ 5. Stream out    │  never buffer the whole tree
  └────────┬─────────┘
           ▼
     📊 CSV   📋 JSON   🗂️ XML
```

> ⚠️ **Step 5 is an architectural decision, not an optimisation.** A
> million-file tree must stream rows to the writer as it walks. Collecting
> everything in memory first works beautifully in testing and dies on the
> first real archive.

## 🧩 One Engine, Two Faces

```
        ┌──────────────────┐
        │   SCAN ENGINE    │   ← the only implementation
        └────────┬─────────┘
                 │
        ┌────────┴─────────┐
        ▼                  ▼
   ┌─────────┐      ┌─────────────┐
   │   CLI   │      │     GUI     │
   │ scripts │      │ builds the  │
   │ cron    │      │ same command│
   │ CI      │      │ then runs it│
   └─────────┘      └─────────────┘
```

The GUI is a **thin wrapper that composes a CLI invocation** and hands it off —
so a scan configured by clicking can always be copied into a script later, and
the two can never disagree about results.

> ⚠️ If the GUI ever grows its own scanning path, the products have forked.
> This constraint is the design.

## 🧩 Output Formats

| Format | For | Note |
|---|---|---|
| 📊 CSV | Spreadsheets, quick audits | What every other tool offers |
| 📋 JSON | Scripts, notebooks, APIs | The likely default in practice |
| 🗂️ XML | Legacy and enterprise intake | ⚠️ Confirm real demand before equal investment |

---

## 🎯 Use Cases

- 🏛️ **Compliance inventory** — exhaustive, timestamped listing of a shared drive
- 💾 **Backup verification** — diff two scans, catch what went missing
- 🎞️ **Media cataloguing** — index a photo library by EXIF, not filename
- 🔁 **Migration input** — feed a DAM or asset tracker in the format it wants
- 🔍 **Forensic trail** — preserve a directory's exact state outside the filesystem

Diff mode is what turns a lister into an audit tool:

```
  scan_monday.json  ──┐
                      ├──►  + 14 added   − 3 removed   ~ 7 modified
  scan_friday.json  ──┘
```

## 🏗️ Design Constraints

| Concern | Decision |
|---|---|
| Attributes differ per OS | Normalize Windows attrs and POSIX permissions into one schema |
| Metadata libraries | Each format adds a dependency — **pick a scoped list and stop** |
| Huge trees | Streaming writer, incremental output |
| GUI drift | GUI only ever emits CLI commands |

## 🚧 Build Plan

| # | Stage | Done when |
|---|---|---|
| 1 | Core CLI: walk + base metadata + CSV | A folder inventories to CSV |
| 2 | JSON and XML writers | Same scan, three formats, same data |
| 3 | Filtering engine | Name, ext, date, depth, size, attributes |
| 4 | Format-specific metadata | EXIF, ID3, document properties |
| 5 | Diff/compare mode | Two scans → added/removed/modified |
| 6 | GUI front end | Builds and runs CLI-equivalent commands |
| 7 | Packaging | Native binaries for all three platforms |

---

## ⚠️ Risks

- 📦 Chasing every file format is unbounded scope — define the supported list and hold it
- 🧠 Memory on million-file trees — streaming from stage 1, not retrofitted
- 🪟 Cross-platform attribute differences need a normalized schema or output becomes OS-specific
- 🗂️ XML may be nobody's first choice today — validate demand before matching effort
- 🔗 GUI/CLI drift is the one failure that breaks the whole premise

---

## ✅ Definition of Done

`fileinspector /archive --format json --exif > inventory.json` produces a
complete, streamed inventory of a million-file tree on any of the three
platforms — and the GUI produces byte-identical output for the same scan.
