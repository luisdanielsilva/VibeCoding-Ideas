FileInspector is a lightweight, cross-platform utility that walks a directory tree and produces a structured inventory of every file it finds — name, path, size, timestamps (created/modified/accessed), and any extended metadata the file format exposes (EXIF for photos, ID3 for audio, page count and author for documents, and so on). Unlike most “list files” utilities, which only export to CSV, FileInspector can output the same scan as JSON, XML, or CSV, so the same tool works equally well feeding a spreadsheet, a script, or a downstream system that expects structured data.

It's loosely inspired by JAM Software's FileList, a long-standing Windows-only command-line tool built for exactly this: generating a directory listing for compliance documentation, inventory audits, and metadata extraction, with filtering by file name, extension, timestamp, directory depth, size, or attributes. FileInspector keeps that same command-line-first design — so it slots into existing scripts, cron jobs, or CI pipelines without any UI — but is written to run identically on macOS, Windows, and Linux, and pairs the CLI with an optional GUI for people who'd rather point-and-click a scan than remember flags.

The GUI isn't a separate product bolted onto the CLI as an afterthought — it's a thin, optional front end that builds the exact same command the CLI accepts, then hands it off, so a scan configured visually can always be reproduced by copying the equivalent CLI invocation into a script later. That single-engine design keeps CLI and GUI results guaranteed identical and avoids maintaining two independent scanning implementations.

Typical use cases: producing an inventory of a shared drive or archive for compliance/audit purposes; documenting exactly what's on a backup before or after it runs, to catch missing or unexpectedly-added files; cataloging a media library (photos/audio/video) by its embedded metadata rather than just filenames; feeding a file inventory into another system (a DAM, an asset-tracking spreadsheet, a data-migration script) via whichever of JSON/XML/CSV that system expects; and forensic/audit trails where a timestamped, exhaustive listing of a directory's exact state needs to be preserved outside the filesystem itself.
