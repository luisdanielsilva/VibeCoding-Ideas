> 📈 **StockSentinel** watches your tickers in real time and emails you the
> moment something moves — not at end of day, and not as a bare notification
> but as a decision prompt.

A self-hosted tracker for a small circle of trusted users. Each ticker is
either **Watching** (a candidate) or **Holding** (a position with cost basis
and quantity), and the app monitors both continuously.

---

## ⚙️ How It Works

```
   Finnhub WebSocket ──── live ticks ────┐
                                         ▼
                            ┌─────────────────────────┐
                            │     ALERT ENGINE        │
                            │  evaluate every rule    │
                            │  against every tick     │
                            └───────────┬─────────────┘
                                        │ match
                                        ▼
                            ┌─────────────────────────┐
                            │  📧 email in seconds    │
                            │  ┌───────────────────┐  │
                            │  │ AAPL −20% today   │  │
                            │  │ [Buy] [Sell]      │  │
                            │  │ [Hold] [Dismiss]  │  │
                            │  └───────────────────┘  │
                            └───────────┬─────────────┘
                                        ▼
                                  decision logged
                                  to alert history
```

> ⚠️ **This needs a persistent server.** A continuously-open WebSocket is
> incompatible with serverless deploys. Decide the hosting model before writing
> the first line — it constrains everything else.

## 🧩 Alert Rules

| Rule | Fires when | Typical use |
|---|---|---|
| 📉 Below price | Price < threshold | Entry target reached |
| 📈 Above price | Price > threshold | Exit target reached |
| ⚡ % drop | Intraday fall exceeds N% | Something happened — go look |
| 🌊 Sudden move | Fast move either way | Volatility event |

The email is the product. A notification says *what happened*; this asks
*what do you want to do* — **Buy / Sell / Hold / Dismiss** — and records the
answer, so the alert history becomes a log of your own decisions.

## 🖥️ The Views

| View | Shows |
|---|---|
| 👁️ Watchlist | Candidates, live prices, distance to target |
| 💼 Portfolio | Positions, cost basis, P&L per holding and aggregate |
| 📊 Chart | 1D · 5D · 1M · 6M · YTD · 1Y · 5Y · All |
| 🔬 Historical Analysis | All-time high/low with date markers, drawdown chart |
| 🏦 Financials | Market cap, P/E, EPS, beta, 52-week range, volume |
| 📰 News | Last 3 months of headlines — **only when requested** |

News is deliberately on-demand. A background news feed becomes noise, and
noise is what this tool exists to filter.

## 🏗️ Stack

| Layer | Choice | Why |
|---|---|---|
| App | Next.js 15 + TypeScript | |
| UI | Tailwind + shadcn/ui | |
| Data | PostgreSQL + Prisma | Relational — users own everything |
| Prices | Finnhub WebSocket + REST | Live ticks, historical OHLCV |
| Charts | TradingView Lightweight Charts | Purpose-built, tiny |
| Email | Resend | Transactional deliverability |
| News | Google News RSS | Free, no key, fetched on demand |
| FX | Live rate API | EUR/USD toggle throughout |

**Data model:** `users` · `sessions` · `watchlist_entries` · `positions` ·
`alert_rules` · `alert_history`. Every row is scoped to a user — isolation is
a schema property, not a query convention.

## ⚠️ Risks

- 🔌 Finnhub free tier caps WebSocket connections and messages
- 🖥️ Persistent server required — rules out serverless entirely
- 📧 Deliverability needs a real transactional service, properly configured
- 📰 Google News RSS may change shape or rate-limit
- 💱 FX adds a second external dependency in the hot path
- 🔐 Multi-user auth means sessions, passwords and per-user isolation done properly

---

## ✅ Definition of Done

A holding drops 20% intraday. Within seconds an email arrives naming the
stock, the move and the position's P&L, with four buttons. The click is logged.
Nobody was watching a screen.
