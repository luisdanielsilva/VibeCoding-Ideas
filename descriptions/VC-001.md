> 🧹 **DupSweep** reclaims disk space by finding *provably* identical files —
> SHA-256, not filename guesswork — and can never delete your last copy.

Most duplicate finders fail in one of two directions: they match on name and
size and delete files that merely looked alike, or they hash everything and
take all night. DupSweep does neither. It funnels candidates through three
widening filters so the expensive work only ever runs on files that are still
plausibly identical.

---

## 🎯 The Problem

| Approach | Failure |
|---|---|
| Match by filename | `IMG_001.jpg` and `IMG_001 (1).jpg` may be different photos |
| Match by size | Thousands of 4 KB files collide by coincidence |
| Hash every file | Correct, but unusably slow on a 2 TB drive |
| Delete by rule | One bad rule deletes the *only* remaining copy |

---

## ⚙️ How It Works

```
   ┌────────────────┐
   │  Select roots  │  local · external · OneDrive · Google Drive
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 1. Walk tree   │  path, size, mtime — no reads yet
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 2. Group size  │  unique size ⇒ unique file ⇒ discarded
   └───────┬────────┘      (kills ~90% of candidates, zero I/O)
           ▼
   ┌────────────────┐
   │ 3. Head hash   │  first 4 KB only — cheap tiebreak
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 4. SHA-256     │  full hash, thread pool, survivors only
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 5. Group sets  │  equal hash ⇒ proven duplicate
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 6. Auto-select │  rules pick the keeper
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 7. Safety Lock │  ⛔ veto: never zero survivors in a set
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ 8. Move to bin │  OS trash, never unlink · every action logged
   └────────────────┘
```

Steps 2 and 3 are the entire performance story. Step 7 is the entire safety
story, and it is a hard invariant rather than a warning dialog: **a duplicate
set must always end the operation with at least one file still on disk.**

---

## 🧩 Core Features

- 🔐 **SHA-256 verification** — zero false positives, by construction
- ⚡ **Multi-threaded hashing** — a thread pool sized to core count
- ⛔ **Safety Lock** — structurally prevents deleting every copy
- 🎛️ **Auto-selection rules** — keep oldest / newest / shortest path / preferred root
- 🖼️ **Media & hidden-file filters** — scope a scan to what matters
- 📝 **Action log** — what moved, from where, when, and why

## 🏗️ Architecture

| Layer | Choice | Why |
|---|---|---|
| macOS app | Swift + SwiftUI | Native feel, Finder integration, no runtime |
| Cross-platform | Python + PySide6 | One port covers Windows and Linux |
| Hashing | SHA-256, streamed in chunks | Constant memory regardless of file size |
| Deletion | OS trash APIs | Recoverable — never `unlink` |
| Licensing | Cryptographic key check | Offline validation, no phone-home |

> ⚠️ **Memory is the real constraint.** A multi-million-file scan must stream
> its index to disk rather than hold every path in RAM. Treat the index as a
> database, not a dictionary.

## ☁️ Next Phase — Cloud Duplicates

The hard part is that cloud-synced folders lie: a file can appear in the
filesystem while its contents live only on a server.

1. 🔑 Register an app in Microsoft Entra, then authenticate by OAuth 2.0 device-code flow
2. 📡 Crawl OneDrive through the Graph API — names, sizes, paths, **and the hashes the API already provides**
3. 🔗 Merge cloud and local results into one duplicate report
4. 🔁 Repeat the pattern for Google Drive, iCloud Drive and Dropbox

> 💡 Ask the API for its stored hash instead of downloading files to hash them
> locally. Downloading a cloud-only file to hash it defeats the purpose of
> having it in the cloud.

---

## ⚠️ Risks

- 🧠 RAM on multi-million-file scans → stream the index, never hold it all
- 🗑️ Trash semantics differ per OS → abstract behind one interface early
- ☁️ Cloud-only placeholder files → detect and skip, never force a download
- 🎯 Perceptual image matching is a *different product* — it finds *similar*, not *identical*. Keep it behind its own clearly-labelled mode.

---

## ✅ Definition of Done

A user points DupSweep at a 2 TB drive, gets a duplicate report with no false
positives, applies a rule to select keepers, deletes the rest to the trash, and
can read a log of exactly what happened — **with at least one copy of every
file still on disk, guaranteed.**
