> 📅 **Agenda Creator** collects the topics, finds the slot that costs the
> group least, builds the agenda, and sends the invites — so nobody runs
> another scheduling thread.

Organising a workshop for twelve people is three unpleasant jobs: chasing
everyone for topics, finding a time that works, and assembling the result into
a schedule people can actually follow. All three are mechanical. All three get
done by hand.

  create workshop

        │                           mark availability
        │                           set priority
        │                                 │
        │                                 ▼
        │                        ┌──────────────────┐
        │                        │ constraint solver│
        │                        │  maximize: heads │
        │                        │  respect: TZ,    │
        │                        │   work hours,    │
        │                        │   must-attends   │
        │                        └────────┬─────────┘
        │                                 ▼

## 🧩 What the Solver Optimises

| Constraint | Type | Behaviour |
|---|---|---|
| Must-attend available | 🔴 hard | Slot is invalid without them |
| Inside working hours (local) | 🔴 hard | Per participant timezone |
| Total attendance | 🟢 maximize | The primary score |
| Topic priority covered | 🟢 maximize | High-priority topics must fit |
| Fragmentation | 🔵 minimize | Prefer one block over three |

> ⚠️ **Timezones are the whole problem.** Store every timestamp in UTC, convert
> only at the edges, and never compare naive datetimes. A workshop spanning
> three continents has no "9am".

## 🏗️ Stack

| Layer | Choice |
|---|---|
| App | Next.js 15 + TypeScript |
| UI | Tailwind + shadcn/ui |
| Input | Web form + optional Excel/CSV upload |
| Calendar | ICS generation first; Google/M365 APIs later |
| Email | Transactional service with templates |

> 💡 Ship **ICS attachments before calendar API integrations.** An `.ics` file
> works with every calendar on earth and needs zero OAuth consent screens.
> API integration is a convenience upgrade, not the mechanism.

## ⚠️ Risks

- 🌍 Multi-timezone scheduling — the core difficulty, not an edge case
- 🔑 Calendar API permissions vary wildly by org; many will never grant them
- 🐌 Participants are slow — the tool must work with partial responses and chase the rest
- 📧 Deliverability: invites landing in spam make the product useless

---

## ✅ Definition of Done

An organizer creates a workshop, shares one link, and — without sending a
single follow-up message — ends up with a ranked slot recommendation, a
time-boxed agenda, and calendar invites in everyone's calendar.
