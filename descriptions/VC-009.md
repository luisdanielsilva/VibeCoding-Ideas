> 🔧 **SmartBOM Optimizer** reads a BOM from any major PCB tool, finds the
> parts that are secretly the same part, and proposes consolidations — with a
> € figure attached *only* when the data can honestly support one.

Large hardware projects accumulate near-duplicates: the same resistor value
under three part numbers because three engineers each picked their own.
Reviewing it by hand is slow and genuinely valuable. This automates the review.

---

## ⚙️ How It Works

```
   BOM export (any of 10 tools)
        │
        ▼
  ┌──────────────────────┐
  │ column mapping       │  Designator│Value│Footprint│Qty│MPN
  │ + per-tool presets   │  ↓ normalize to one schema
  └──────────┬───────────┘
             ▼
  ┌──────────────────────────────────────────┐
  │           SIMILARITY ENGINE              │
  ├──────────────────────────────────────────┤
  │ 🟢 Exact      same MPN, many lines       │
  │ 🟡 Near-equiv same value ± tolerance,    │
  │               equivalent footprint       │
  │ 🔵 Flagged    inconsistent spec          │
  │               (one 0.1% among 1% parts)  │
  └──────────┬───────────────────────────────┘
             ▼
  ┌──────────────────────┐
  │ group + confidence   │
  └──────────┬───────────┘
             ▼
  ┌──────────────────────┐
  │ per-LINE review      │  expand group, tick lines
  │ ☑ merge  ☐ keep      │
  └──────────┬───────────┘
             ▼
  ┌──────────────────────┐
  │ exception memory     │  "deliberate second source"
  │ → never re-flagged   │
  └──────────┬───────────┘
             ▼
     optimized BOM, same universal format
```

## 🧩 Confidence Tiers

| Tier | Meaning | Action |
|---|---|---|
| 🟢 **Exact duplicate** | Same PN across lines/BOMs | Merge, sum quantity |
| 🟡 **Near-equivalent** | Same value in tolerance, equivalent footprint & rating | Propose, require review |
| 🔵 **Flagged inconsistency** | Spec outlier in a batch | **Flag only — never auto-merge** |

> ⚠️ **Some duplicates are intentional.** A deliberate second source is not a
> mistake. Review must work at the individual line, not just the group, and an
> unmerged line must be markable as deliberate so future runs stop re-flagging
> it. Without exception memory the tool nags, and a tool that nags gets ignored.

## 💶 The Savings Figure

Shown **only** when the input BOM already contains a cost column. Otherwise
greyed out.

> 💡 Fabricating a savings number without real pricing would undermine every
> other number the tool produces. The greyed-out state is a feature.

## 🏗️ Architecture

| Layer | Choice | Why |
|---|---|---|
| Import | One column-mapping engine + presets | 10 tools, not 10 parsers |
| Normalization | Single internal schema | Everything downstream sees one shape |
| Similarity | Rule-based + AI scoring | Rules for safety, AI for near-equivalence |
| Review UI | Expandable groups, per-line checkboxes | Merging is a decision, not a batch job |
| Memory | Persisted exceptions per BOM | Review gets faster each run |
| Export | Same universal CSV/Excel | Re-importable into the originating tool |
| ERP (opt.) | Live API **or** exported approved list | Restrict to approved + in-stock parts |

**Presets:** Altium · KiCad · OrCAD/Allegro · PADS/Xpedition · EasyEDA ·
Fusion Electronics/Eagle · Zuken CR-8000/CADSTAR · CircuitMaker · DipTrace · Flux.ai

## ⚠️ Risks

- 🔐 ERP access and permissions are the usual bottleneck → ship offline-list mode first
- ⚖️ "Similarity" rules must be conservative — an unsafe substitution is worse than a missed saving
- ✍️ Engineering sign-off remains required before any merge reaches production
- 📄 Some tools export tab-delimited files named `.csv` — detect and normalize, don't trust the extension
- 💶 A savings figure without cost data would be misleading — keep it conditional

---

## ✅ Definition of Done

An engineer uploads a 3,000-line BOM, sees the duplicate groups ranked by
confidence, merges the safe ones and marks two as deliberate, and exports a
BOM that re-imports cleanly into the tool it came from — with a KPI summary
showing distinct part numbers before and after.
