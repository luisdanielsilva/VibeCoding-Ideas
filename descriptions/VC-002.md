> 📓 **VibeCoding Ideas** is a public log of app concepts — the bridge between
> a rough spark and a real build plan, kept honest by being published.

Ideas die in private notes. This portal puts them somewhere public, in a shape
detailed enough to hand straight to an AI and start building. Every idea is a
card; every card opens into a full specification.

---

## ⚙️ How It Works

```
   ideas.json                descriptions/VC-0XX.md
   (structured data)         (the written plan)
        │                            │
        │  fetch on load             │  fetch on modal open
        ▼                            ▼
   ┌──────────────┐            ┌──────────────┐
   │ renderIdeas()│            │renderMarkdown│
   └──────┬───────┘            └──────┬───────┘
          ▼                           ▼
     card grid  ──── click ────►  idea modal
                                      │
                                 ┌────┴─────────────────┐
                                 │ description (md)     │
                                 │ features · stages    │
                                 │ advantages/pitfalls  │
                                 │ roadmap → todo/done  │
                                 └──────────────────────┘
```

**No build step, no backend, no dependencies.** Static files served by nginx,
deployed by `git push`.

---

## 🧩 The Split That Makes It Work

| File | Holds | Edited by |
|---|---|---|
| `ideas.json` | id, title, status, excerpt, features, stages, advantages, pitfalls, roadmap | a small Python script |
| `descriptions/<id>.md` | the long-form build plan | any text editor |

Descriptions used to live inside the JSON as escaped strings. Splitting them
out means prose is written as prose and diffed as text, while the JSON stays
purely structured data.

---

## 🏗️ Stack

| Layer | Choice |
|---|---|
| Markup | Plain HTML, glassmorphism design tokens |
| Logic | Vanilla JS — `renderIdeas()`, `openModal()`, `renderMarkdown()` |
| Data | `ideas.json` + per-idea markdown files |
| Deploy | GitHub Actions → Tailscale → rsync → nginx reload |

> ⚠️ The checkout **is** the web root, and the deploy rsyncs with `--delete`.
> Always commit before pushing, and never remove the nginx rule that returns
> 404 for dotfiles — without it, `.git/` is publicly fetchable.

## ⚠️ Risks

- ✍️ New ideas need manual entry — **and now a matching `.md` file**, or the modal reads "Description unavailable"
- 📚 Idea bloat without execution — status badges are the honesty mechanism
- 🧊 Static hosting caps how interactive this can ever get, by design

## ✅ Definition of Done

Someone lands on the site, scans the grid, opens an idea, and leaves with a
plan detailed enough to start building — without asking a single question.
